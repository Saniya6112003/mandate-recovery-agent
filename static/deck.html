UPI Autopay
Mandate Recovery Agent

Recovering failed autopay debits — and refusing to count a single rupee until a signed webhook proves the money arrived.

The problem

UPI Autopay doesn't fail
like a card does.

A card mandate is a stored credential. UPI Autopay needs a live bank approval on every single debit — so it fails several times more often.

Rail-specific failures

Codes with no card equivalent.

IEFunds blocked by another mandate
VAMandate revoked
QAPaused by the customer
MA0Mandate no longer exists

For several of these, retrying isn't just useless — it isn't permitted.

The task

Three things at once.

01

Diagnose

Why did this debit fail — from the raw NPCI code, not a label.

02

Stay lawful

RBI notice windows, retry caps, mandate state. Some retries are illegal.

03

Prove it

Show the rupee actually arrived — not that an API call succeeded.

How it works

The model proposes.
Code decides what's allowed.

Step 1

Reasoning agent

Reads the decline code, retry history, amount and mandate age. Proposes one bounded action through a forced schema.

Step 2 · always wins

Guardrails

Deterministic code. Reads authoritative mandate status — not the model's diagnosis. Can refuse the recommendation outright.

Step 3

Audit log

One immutable row per decision. Only a signed webhook can set recovered.

Confidence doesn't predict
being right.

With 2–4 wrong cases per run, no single figure is a real measurement — and the sign flips. That instability is the finding.

95% accurate.
And its confidence tells you nothing about when it's wrong.

Which is why the compliance layer is deterministic code — not a better prompt.

Build challenges

What broke, and how I fixed it.

  • My decline codes were fake. Card-style ISO codes with invented prefixes — re-verified every one against a bank's published UPI response code list.
  • The model hallucinated the code book — 42% accuracy. Gave it the verified NPCI reference (the banks' descriptions, deliberately not the answers). 42% → 95%.
  • My tests were calling the live API. Every pytest run created real payment links. Suite time fell 3.2s → 0.94s once blocked — proving the calls had been real.
  • My "immutable" audit log wasn't durable. A redeploy destroyed a verified ₹9,999 recovery. Moved to Postgres — where a duplicate webhook now structurally cannot double-count.
