The customer already
said yes.

The mandate is signed. The money is owed. And on collection day, the debit silently fails — nobody calls anyone, and the merchant simply loses it.

The situation

UPI Autopay doesn't fail
like a card does.

A card mandate is a stored credential. UPI Autopay needs a live bank approval on every single debit — so it fails several times more often, for reasons that have no card equivalent.

IEFunds blocked by another mandate
VAMandate revoked
QAPaused by the customer
MA0Mandate no longer exists

For several of these, retrying isn't merely useless — it isn't permitted.

The task

Three things at once.

1 · DiagnoseWhy did this debit fail?
2 · Stay lawfulRBI notice windows, retry caps, mandate state
3 · Prove itShow the rupee actually arrived

So I built an agent with three parts that decide.

The action

Three who decide.

The Analyst

NAYA

Reads the raw decline code, retry history, amount and mandate age. Proposes one bounded action. Fast, articulate — and sometimes confidently wrong.

The Guard

RAKSHA

Not AI. Deterministic compliance code. Reads the mandate's real status from the bank — not Naya's opinion of it. Never asks how confident she was.

The Auditor

LEKHA

Writes every decision immutably — and refuses to write the word recovered until a cryptographically signed webhook proves the money arrived.

Raksha never looked at the confidence score. She checked mandate state independently — which is why a 96%-confident misdiagnosis still could not produce an unlawful retry.
Why it's built that way

Its confidence tells you
nothing about being right.

Across three sixty-case runs I measured the model's confidence when it was right, against its confidence when it was wrong.

RunAccuracyConfident when rightwhen wrongGap
A93%0.8980.895+0.003
B97%0.8890.940−0.051
C95%0.8940.880+0.014

The gap sits inside the noise and changes sign between runs. With 2–4 wrong cases per run no single figure is a real measurement — and that instability is the finding. That is exactly why Raksha is deterministic code, not a better prompt.

Build challenges

What broke, and how I fixed it.

My decline codes were fake.
Fixed: they were card-style ISO codes with invented prefixes. Re-verified every one against a bank's published UPI response code list.
The guardrail read the answer key.
Fixed: it checked a scoring-only label. Added authoritative mandate status the model never sees — so it blocks even when the diagnosis is wrong.
The model hallucinated the code book. 42% accuracy.
Fixed: gave it the verified NPCI reference — the banks' descriptions, deliberately not the answers. 42% → 95%. A test fails if an answer ever leaks in.
My tests were calling the live API.
Fixed: every pytest run was creating real payment links. Suite time fell 3.2s → 0.94s once blocked — proving the calls had been real.
One malformed reply killed a 60-case run.
Fixed: the schema caught it, but the crash lost 24 cases. Undecidable cases now become auditable human escalations and the batch continues.
My "immutable" log wasn't durable.
Fixed: a redeploy destroyed a verified ₹9,999 recovery. Moved to Postgres — which also made duplicate webhooks structurally unable to double-count.
